title: Zod
description: TypeScript-first schema validation. Define the shape of your data once and use it for validation and types.
---

**Zod** lets you declare a **schema** (the expected shape of some data), then **validate** unknown data against it at runtime. In TypeScript it also **infers the static type** from the schema, so you don't write the type twice.

Use it for:

- form validation (with [React Hook Form](/docs/libraries/forms/react-hook-form)),
- validating **API responses**, so you never trust the backend blindly,
- environment variables, URL search params, `localStorage` data and Server Function input.

```bash
npm i zod
```

<Callout title="Version">These examples use **Zod 4**.</Callout>

## Defining a schema

```ts
import { z } from 'zod';

const UserSchema = z.object({
  name: z.string().min(2, 'Name must be at least 2 characters'),
  email: z.email('Invalid email address'),
  age: z.number().int().min(18, 'Must be 18 or older').optional(),
  role: z.enum(['admin', 'editor', 'viewer']).default('viewer'),
  website: z.url().optional(),
  tags: z.array(z.string()).max(5),
});

// infer the TypeScript type from the schema
type User = z.infer<typeof UserSchema>;
// { name: string; email: string; age?: number; role: 'admin' | 'editor' | 'viewer'; ... }
```

## Validating data

```ts
// parse: returns typed data, or THROWS a ZodError
const user = UserSchema.parse(input);

// safeParse: never throws. Returns { success, data } or { success, error }
const result = UserSchema.safeParse(input);

if (result.success) {
  console.log(result.data.email); // fully typed
} else {
  console.log(result.error.issues);
  // [{ path: ['email'], message: 'Invalid email address', code: 'invalid_format', ... }]
  console.log(z.flattenError(result.error).fieldErrors);
  // { email: ['Invalid email address'], name: [...] }
}
```

Unknown keys are **stripped** by default. Use `z.strictObject({...})` to reject them, or `z.looseObject({...})` to keep them.

## Common types

| Schema | Accepts |
| --- | --- |
| `z.string()`, `z.number()`, `z.boolean()`, `z.date()` | Primitives |
| `z.email()`, `z.url()`, `z.uuid()`, `z.iso.date()` | String formats |
| `z.string().min(1).max(100).trim()` | Length checks and transforms |
| `z.number().int().positive().max(10)` | Number checks |
| `z.literal('admin')`, `z.enum(['a', 'b'])` | Exact values |
| `z.array(Item)`, `z.tuple([z.string(), z.number()])` | Arrays |
| `z.object({...})`, `z.record(z.string(), z.number())` | Objects |
| `z.union([A, B])`, `z.discriminatedUnion('type', [A, B])` | One of several shapes |
| `.optional()`, `.nullable()`, `.default(x)` | Missing, null and default values |

## Coercion

Form inputs and URL params are **strings**. `z.coerce` converts them before validating:

```ts
const Params = z.object({
  page: z.coerce.number().int().min(1).default(1),   // "2" → 2
  showArchived: z.stringbool().default(false),       // "true"/"1"/"yes" → true
});

Params.parse({ page: '3', showArchived: 'true' }); // { page: 3, showArchived: true }
```

## Custom rules with `refine`

```ts
const SignupSchema = z
  .object({
    password: z.string().min(8),
    confirmPassword: z.string(),
  })
  .refine((data) => data.password === data.confirmPassword, {
    message: "Passwords don't match",
    path: ['confirmPassword'], // which field the error belongs to
  });
```

## Transforms

```ts
const Slug = z.string().trim().toLowerCase().transform((s) => s.replace(/\s+/g, '-'));
Slug.parse('  Hello World '); // "hello-world"

type In = z.input<typeof Slug>;   // string (before the transform)
type Out = z.output<typeof Slug>; // string (after the transform)
```

## Composing schemas

```ts
const Address = z.object({ city: z.string(), zip: z.string().length(6) });

const Customer = UserSchema.extend({ address: Address }); // add fields
const PublicUser = UserSchema.pick({ name: true });       // keep some
const UserUpdate = UserSchema.partial();                  // all optional
const NoEmail = UserSchema.omit({ email: true });         // remove some
```

## Validating API responses

```ts
const PostSchema = z.object({ id: z.number(), title: z.string(), body: z.string() });
const PostsSchema = z.array(PostSchema);

export async function getPosts() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts');
  return PostsSchema.parse(await res.json()); // throws if the API shape changed
}
```

If the backend changes the shape, you get a clear error at the boundary instead of `undefined` errors deep inside your components.

## Validating environment variables

```ts title="src/env.ts"
const EnvSchema = z.object({
  VITE_API_URL: z.url(),
  VITE_SENTRY_DSN: z.string().optional(),
});

export const env = EnvSchema.parse(import.meta.env); // fails fast at startup
```

<Callout type="warn" title="Zod 3 → 4 changes">
  If you read older tutorials: `z.string().email()` is now `z.email()`; the `required_error` and `invalid_type_error` options were replaced by a single `error` option; `.flatten()` became `z.flattenError(err)`; and `.strict()` / `.passthrough()` became `z.strictObject` / `z.looseObject`.
</Callout>
