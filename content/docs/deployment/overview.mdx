---
title: Static vs Server Deployment
description: Which React apps can be deployed as static files, which need a running server, and how to choose.
---

Every React app is deployed in one of two ways:

| | Static deployment | Server (dynamic) deployment |
| --- | --- | --- |
| What you upload | A folder of files: HTML, JS, CSS, images | An app that **runs** (Node.js process, serverless functions or a container) |
| HTML is generated | Once, at **build time** (or in the browser) | On **each request** (or cached per request) |
| Hosting | Any static host or CDN: GitHub Pages, Netlify, Cloudflare Pages, S3 | Vercel, Netlify Functions, Render, Railway, Fly.io, a VPS, Docker or Kubernetes |
| Cost | Usually free | Free tiers exist; you pay for compute |
| Scaling | Automatic (it's just files on a CDN) | You or the platform scale servers or functions |
| Can do | UI, client-side data fetching from external APIs | Everything static can, plus SSR, auth cookies, Server Components, Server Functions, API routes, database access |

## What does your React setup produce?

| Setup | Build output | Deployment |
| --- | --- | --- |
| **Vite SPA** (`npm create vite`) | `dist/` static files | ✅ Static |
| **Create React App** (legacy) | `build/` static files | ✅ Static |
| **Next.js** with `output: 'export'` | `out/` static files | ✅ Static (no SSR, API routes, middleware or image optimisation) |
| **Next.js** (default) | `.next/` + a Node server | 🖥️ Server |
| **React Router framework mode** with `ssr: false` | `build/client/` | ✅ Static (SPA mode) |
| **React Router framework mode** (SSR) | `build/server` + `build/client` | 🖥️ Server |
| **Astro / Gatsby with React** | Static by default | ✅ Static (SSR adapters optional) |
| **Vite SPA + your own Express/Nest API** | `dist/` + a Node API | ✅ Static frontend + 🖥️ server API, deployed separately |

## Rendering strategies and where they run

| Strategy | When HTML is made | Needs a server? | Good for |
| --- | --- | --- | --- |
| **CSR** (client-side rendering) | In the browser | ❌ | Dashboards and apps behind a login |
| **SSG** (static site generation) | At build time | ❌ | Docs, blogs, marketing pages |
| **SSR** (server-side rendering) | Per request | ✅ | Personalised or always-fresh pages, SEO with live data |
| **ISR** (incremental static regeneration) | Build time, refreshed in the background | ✅ | Large catalogues that change occasionally |
| **RSC + Server Functions** | Per request or cached | ✅ | Full-stack React (Next.js App Router) |
